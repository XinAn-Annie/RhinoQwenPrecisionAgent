# 三案例真实小样本对比

日期：2026-10-30；模型：`qwen3.8-flash`；执行层：McNeel Rhino MCP Platform 0.3.0 + Rhino 8.33。

固定案例为精确盒子、三件式圆桌、两件式支柱/顶板。每个案例都在真实 Qwen 和真实 Rhino 文档中执行，并在案例间撤销。完整机器可读结果见 `real_comparison.json`。

| 指标 | 基线：Qwen 直接生成 `run_python` 工具调用 | 实验：ModelingSpec + 确定性验证 + 修复 |
|---|---:|---:|
| 首次通过率 | 0/3 | 2/3 |
| 最终通过率 | 0/3 | 3/3 |
| 约束满足率 | 0/15 | 39/39 |
| 可测量案例的平均最大绝对尺寸误差 | 不可测（对象未成功落入文档） | 0.0 mm |
| MCP/脚本工具失败 | 3 | 0 |
| 自动修复 | 0 | 1 |
| 人工调整 | 0 | 0 |
| 平均耗时 | 16.423 s | 74.362 s |
| 记录的生成 Token | 5,242 | 13,204 |

基线给 Qwen 真实 `run_python` Function，并在执行前使用本地安全检查阻断网络、Shell、进程和文件能力；三个直接生成脚本均进入 MCP，但 payload 报脚本执行失败，因此没有形成可测量对象。实验路径先验证 ModelingSpec，再由确定性本地执行器构造受限 Rhino Python：盒子和圆桌首次通过；第三例主动把第二对象偏移 25 mm，MCP 返回成功但验收失败，Qwen 选择 `repair`，撤销重建后 13/13 通过。

这是三个固定案例的工程 PoC，不是统计实验；结果只证明本机、当前上游版本与这些提示下的行为，不能外推为普遍准确率提升。基线的脚本失败也不代表 Qwen 一般能力，只说明“直接生成并执行 Rhino Python”在此小样本中缺少结构化规格与确定性执行器时不可靠。
